# Testing GHerrit

Use `ci/validate.sh` for production builds, formatting, strict Clippy, all
hermetic tests, doctests and task-marker checks. `unit`, `semantic`, `adapters`,
`hooks` and `cli` select useful layers while developing. The full helper remains
the submission check. CI also runs the native Windows suite; a macOS pass does
not establish Windows process behavior.

## Choose the boundary that can falsify the claim

| Claim | Evidence owner |
| --- | --- |
| Raw identities, canonical JSON, versions, markers, ref/receipt grammar | Unit tests beside the owning codec; generated byte and duplicate-key cases |
| Literal graph, config scopes, native paths, installation, push leases | Real Git repositories in utility and process tests |
| Subprocess ownership, deadlines, output bounds and cleanup | `src/subprocess/tests.rs` plus platform implementations |
| Exact HTTP requests, pagination and single-send receipts | GitHub transport contract tests and raw HTTP arrival accounting |
| Ordered effects, crash recovery and overlapping plans | Production consuming driver against the semantic external world |
| Actual hook argv/stdin, recursion, clone recovery and lifecycle | `tests/hooks.rs` and `tests/pre_push/` with real Git and the local HTTP fake |
| Current hosted contracts | Explicit disposable-target tool, outside normal tests |

The [architecture map](../design/architecture.md) locates modules. The
[publication contract](../design/pre-push.md) states assumptions which the tests
must not silently strengthen. A green test establishes its asserted witness,
not all schedules or all provider behavior.

## Fixtures and observations

`testutil::TestContext` creates isolated Git repositories, home/config files,
environment and optional local GitHub server. Commands are bounded. Prefer
capability builders only when the scenario needs them. Production and the
feature-gated test driver are separate executables: production does not read
test endpoints or dispatch fixture interception, including all-feature builds.

The HTTP fake counts every arrival before JSON or GraphQL validation. Decoded
operation traces are a separate observation. Unexpected protocol violations fail
teardown; a negative test must explicitly consume the expected violation count.
Zero decoded operations alone cannot establish that no HTTP request was sent.
Strict teardown also checks unconsumed faults, worker errors and panics.

Native paths, complete shim bytes and executable modes are checked at their
actual boundaries. The commit-message suite compares installed-hook outcomes
with unhooked Git across cleanup modes and comment/trailer configuration. Its
existing-identity fast path must leave messages byte-exact and avoid unnecessary
committer/entropy work.

## External storage and concurrency

`testutil::git_model::RefStore` stores literal refs. Advertisement-time equal-OID
no-op decisions and lease checks are distinct from receive-time atomic old-OID
checks on transmitted commands. A native bare-Git differential scenario compares
success and every raw ref for lightweight A→B→A and distinct-annotation control
schedules. Keep raw annotation identity distinct from the peeled commit.

The semantic world stores raw current refs independently from its history
ledger. It must not authorize version creation using ledger length: Git has no
such namespace-wide condition. Production prepared annotation OIDs reach that
world unchanged. Coherence is asserted after storage effects and independently
checked before observed facts become publication authority.

Scenarios include retained plans, repeated revisions, partial/lost receipts,
canonical marker contenders, arbitrary complete mutation-alias subsets,
duplicate repair and stable-intent recovery. The three-retained-attempt ABA case
uses production planning, alongside the native Git witness. Shape comparisons
may erase opaque fresh tokens where equality is intentionally irrelevant; exact
ref assertions must retain those tokens. Never normalize away a differing
publication revision, target, stage or canonical number.

Terminal lifecycle and terminal projection fields remain separate facts. A stale
mutation may update fields then return CLOSED/MERGED. An unusable receipt stops
later effects; it does not prove that this write never occurred. Likewise a lost
acknowledgement does not imply a rejected effect. Fresh recovery starts from new
observations, without replaying a transmitted token-bearing action.

Bounded exploration covers the implemented scenarios and supported envelope.
It is not exhaustive verification of GitHub, native landing, independent lifecycle
changes, default movement or interruptible adoption. Keep provider assumptions
visible rather than repairing a failing model by preventing an external action
that the service can actually perform.

## Snapshot and cost checks

Before accepting a snapshot, inspect its owning state/effect oracle and the
exact diff. Update only the selected scenarios; do not rewrite unrelated output
to make a suite green. Preserve exact receipt names and raw refs even when
human-readable diagnostics redact paths or OIDs. A version archive assertion
must choose explicitly between raw object identity and its peeled revision.

[Performance guidance](performance.md) describes bounded operation counts and
their measurement method. Tuple and marker budgets describe this implementation,
not a neutral requirement for every future protocol. Exact process counts are
workload-specific and are not elapsed-time benchmarks.

## Hosted probes

The [provider tool](hosted-contracts.md) requires an explicit disposable target,
mutation authorization and a fresh journal. Normal Cargo tests only compile it;
they never run hosted mutations because of credentials or environment variables.
Journals distinguish submitted requests from validated receipts and cleanup
ownership. Probe availability does not establish that a probe was run.
